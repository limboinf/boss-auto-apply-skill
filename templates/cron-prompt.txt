- 库：<repo>/scripts/pipeline_v2_lib.js（makePipelineV2 + 纯逻辑可离线测）、<repo>/scripts/profile.js（loadProfile）、<repo>/scripts/ego_browser_adapter.js（makeH）
- 身份与规则：<repo>/data/profile.json（loadProfile() 读；改规则改这里，不要临场改库）
- 台账：<repo>/data/applied-ledger.json

- 午班先查 runs/YYYY-MM-DD-AM/shortlist.json：未消化完优先吃它，不重滚列表（细筛 runDir 仍用 AM 目录，checkpoint 才连续）

【规则】全部在 profile.rules，库执行：黑名单、学历、岗位类型、标题/JD 主语言红线（加分/可选豁免）、薪资 Max ≥ minSalaryK、JD 必含关键词、猎头挂单（默认过滤）、外包岗（默认 NEEDS_REVIEW 交你判断）。列表页薪资打码由库解码（每批开 1 页校验），不用管。

【v2 状态机：两个独立 heredoc 轮次，串行走完】
0. 每轮 heredoc 开头：import 三个库 → profile = loadProfile() → taskSpace（首轮建，后续 taskSpace(<id>) 复用）→ pipe = makePipelineV2(makeH(page), profile)。
1. 粗筛轮 DISCOVER：`pipe.discover(runDir, page)`（关键词/轮数取 profile.search，5 词约 200s）。登录预检内置，失效即停并 handOff 交扫码；游客态直接终止本轮写 BLOCKED 报告。
2. 细筛轮 SCREEN：`pipe.screenLoop(runDir, page)`（上限/间隔取 profile.pacing）。逐岗开详情→判定→通过立即发送→当场记账→随机等待→下一岗。绝不攒批统一发。中断恢复自动跳过终态公司，FAILED 重试。rounds 不够时多轮 heredoc 续跑直到 maxSend 达标或 shortlist 耗尽。跑完看 details.jsonl 的 NEEDS_REVIEW（外包岗）：读 jd 摘要自行判断，技术栈高度匹配才 `pipe.sendReviewed(runDir, co)` 补发，报告里单独标注。
3. 收尾 LEDGER：`v2.updateLedgerFromCheckpoint(v2.ledgerPath(), runDir+'/checkpoint.jsonl', 今日日期, runDir+'/details.jsonl')`（幂等）。

【执行约束】
- ego-browser nodejs 是 ESM 且支持顶层 await：库用 `(await import(path)).default` 加载（没有 require）。整个批次只建一个 task space。
- 每 heredoc 单轮 ≤550s（terminal timeout 显式 550+）；粗筛约 3-4 分钟、细筛 7 家约 5-8 分钟，超时拆轮续跑。
- 遇 user is controlling / task space 被接管：立即停，报告已完成和未完成，不抢回。
- 发送验证以 verifyCurrent 为准（active 会话 + own hook + profile.links 全部完整出现 + 草稿清空）。
- 最终报告必须区分：发现卡数/粗筛通过数/细筛判定数（过/淘汰+原因分布/外包待判断数及处理结果）/实际发送数/验证通过数/台账累计/checkpoint 路径；不把"启动/unknown"说成完成。
